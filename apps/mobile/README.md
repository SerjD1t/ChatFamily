# ChatFamily для Android (Capacitor)

Текущая сборка: **0.5.0** — проверка и установка обновлений APK с сервера.
[Сценарий, публикация и проверки](../../docs/mobile/updates.md). Первая установка — вручную.
Ограниченный кэш вложений и «Память устройства» из 0.4.0 сохранены.

Android-оболочка на Capacitor 8.4.3. С версии 0.3.0 загружает общий веб-интерфейс
с `https://www.chatfamily.site`; APK содержит нативные плагины и экран восстановления
соединения. `server.url` используется намеренно для этой архитектуры (в документации
Capacitor предназначен прежде всего для live reload), с дополнительными ограничениями.

## Структура

```text
apps/mobile/
  capacitor.config.json       # приложение, точный серверный HTTPS origin
  package.json / package-lock.json
  scripts/copy-web.mjs        # встроенный экран ошибки и публикация JS runtime
  shell/                     # только локальные index.html и offline.html
  android/                   # Android Studio / Gradle проект
    app/src/main/java/site/chatfamily/app/
      MainActivity.java
      share/
        IncomingSharePlugin.java  # локальный плагин Capacitor
        ShareStore.java           # закрытое хранилище принятых файлов
        ShareWorker.java          # WorkManager: загрузка и повторы
  www/                       # генерируется, не редактировать и не коммитить
web/mobile/                  # общий адаптер API и окно входящих вложений
docs/mobile/android.md       # архитектура, ограничения и приёмка
```

## Сборка

Нужны Node.js 22+, JDK 21, Android SDK Platform 36 и компоненты SDK, требуемые Gradle.
Лицензии SDK принимает разработчик. Путь SDK задаётся через `ANDROID_HOME` в окружении.
Не сохраняйте секреты/параметры серверного подключения в Gradle или исходниках.

```powershell
cd apps/mobile
npm ci
npm run sync
cd android
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`.
Для Android Studio: `npm run open` из `apps/mobile`.
Debug APK разрешён для текущего распространения и обновлений по решению пользователя;
в предложении обновления он обозначается как тестовый. Подпись должна совпадать с установленным APK.
На Windows также доступен `./scripts/build-android.ps1`. Если Java не доверяет
сертификатам, уже доверенным Windows, передайте `-UseWindowsTrustStore`: используется
системное хранилище доверия только на время сборки, проверка TLS не отключается.
Ключ release-подписи согласуется отдельно; механизм обновления работает и с текущей debug-подписью.

Начиная с APK 0.3.0 интерфейс загружается с `https://www.chatfamily.site`.
После изменений `web/` обновляется сервер; пересборка APK нужна только для нативного
кода, зависимостей, конфигурации оболочки и встроенного экрана ошибки.
Уже открытая страница получает новую версию при следующей загрузке, не посреди ввода.
`npm run sync` копирует в APK только `shell/`, а закреплённый официальный JS-runtime
Capacitor публикует в `web/mobile/capacitor-core.js`. Старые APK остаются автономными
копиями старого интерфейса: для перехода на новую архитектуру установить 0.3.0.
Серверная часть должна быть установлена **до** тестирования APK: CORS для origin
`https://chatfamily.site`, маршрут `/api/v1/mobile/shares/{requestID}`, миграция 019.
Проверить актуальность более ранних миграций перед переносом; не удалять базу.

## Почему локальный плагин

Capacitor обеспечивает оболочку и JS/native-мост. Приём Intent реализован небольшим
плагином проекта, а не сторонним Share Target: файлы сразу копируются из временных
`content://` URI в закрытое хранилище, очередь переживает перезапуск процесса,
отправка привязана к аккаунту и идемпотентному ключу. Тела файлов не передаются через JS/base64.
Официальный `@capacitor/share` решает обратную задачу — передачу наружу.

Установка приложения не меняет обычный браузерный клиент. Долгое нажатие на отправку
для прикрепления файлов сохранено. Push браузера сохранён; нативные уведомления
используют официальный Capacitor Push Notifications и Firebase Cloud Messaging.

## Настройка Firebase

Зарегистрировать Android-пакет `site.chatfamily.app` в Firebase. Скачать клиентскую
конфигурацию и ключ сервисного аккаунта в отдельную папку вне репозитория.
Из корня репозитория выполнить `node apps/mobile/scripts/import-firebase.mjs <папка>`.
Импорт проверяет совпадение проекта и пакета, сохраняет настройки только в
исключённый из Git и Docker `settings.local.json`, не выводя значения.
Gradle встраивает только публичный блок `firebase.android`; `firebase.serviceAccount`
не включается в APK. Затем пересобрать приложение.

Серверу нужна миграция 020 и `FCM_SERVICE_ACCOUNT_JSON` через защищённое окружение.
На VPS используйте `python3 deploy/compose.py`: обёртка читает host-only
`settings.local.json` (0600) и передаёт только `firebase.serviceAccount`.
Не монтируйте полный файл в app: он содержит также ключи резервных копий.
Не выводить конфигурацию в логи. Сначала обновить
сервер, затем устанавливать новый APK. Без серверной настройки уведомления недоступны.
Проверить включение/отказ, фон и закрытый клиент, переход в чат, отключение и смену
аккаунта. FCM требует поддерживаемых сервисов Google; force-stop Android блокирует
уведомления до запуска приложения. Текст push общий, без содержимого сообщения.

На Huawei/EMUI без GMS этот канал не работает. Huawei Push Kit отложен до решения
вопроса с регистрацией приложения в Huawei Developer/AppGallery Connect.
