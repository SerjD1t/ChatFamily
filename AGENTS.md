# Правила ChatFamily

Применяются ко всем задачам проекта. Перед работой прочитай этот файл; по затронутой области — ссылки ниже. Не считай старую переписку доказательством текущего состояния сервера.

## Работа и безопасность

- Выполняй текущий запрос; диагностика не разрешает исправления. Разработка по умолчанию локальная. Развёртывание, Git push и оформление релиза — отдельные действия по явному запросу; push не означает релиз.
- Сохраняй чужие и незавершённые изменения. Не сбрасывай рабочее дерево и не удаляй данные без явного разрешения. Для правок используй apply_patch, для поиска — rg.
- Не запускай подагентов без явного запроса пользователя или отдельного требования правил.
- Секреты подключения храни только в корневом settings.local.json. Он должен быть исключён из Git и Docker-контекста; проверяй исключение без вывода содержимого. Не копируй его содержимое в другие файлы проекта.
- Не выводи пароли, токены, cookies, ключи, строки подключения и персональные данные в ответы, логи, документацию, тестовые артефакты или Git. Используй синтетические тестовые данные.
- Не читай секретные файлы целиком в вывод инструмента. Legacy-каталоги pass/ и ssh/, .env, uploads/, data/, APK и ключи подписи не публикуй. Не создавай новые альтернативные локальные хранилища секретов.
- Текущий Compose требует .env, а основная Go-конфигурация — окружение. settings.local.json не загружается автоматически как общая конфигурация. Не обходи правило секретов ради запуска: см. docs/operations.md.
- В work-log.md фиксируй дату, начало/окончание/длительность, запрос, результат, файлы и объекты, проверки, ручную приёмку, что переносилось или предстоит переносить. Без секретов и персональных данных.

## Архитектура и продуктовые требования

- Go + PostgreSQL; HTTP-обработчики в корне, домен в internal/chat, SQL в internal/store, последовательные миграции в internal/store/migrations.
- Общий интерфейс — web/ (JavaScript/CSS); Android Capacitor — apps/mobile/; справка — docs/. Не смешивай нативный код и сервер.
- Личные диалоги, включая диалог с собой («Вы»), глобальны. Переключение семьи влияет только на семейные чаты, группы, участников и семейные функции.
- Роли доступа, категории участников и отображаемый семейный статус — разные понятия. Владелец меняет роли; администратор семьи — категории/статусы и семейные настройки. manage_application позволяет через отдельный раздел управлять всеми семьями, их названиями, составом и ролями (включая владельцев), но не предоставляет автоматически членство, переписку, вложения или семейные дела. Последнего активного владельца нельзя исключить/понизить; изменения ролей сериализуются на семье. Исключение отзывает доступ ко всем чатам данной семьи, не удаляя историю и личные диалоги.
- В личных диалогах и справочниках показывай имя и фамилию; в общем семейном чате — имя и отображаемый статус этой семьи, без фамилии. Категории: ребёнок, родитель, бабушка/дедушка, опекун, родственник.
- Права проверяй на сервере для каждого действия, включая вложения и прямые API-запросы. Удаление аккаунта — только администратору приложения, с подтверждением; аккаунты с историей деактивируются.
- Отправка сообщений/вложений и изменение/удаление своих сообщений — базовые возможности активных участников, не отключаемые глобальными галочками. Проверяй авторство и текущий доступ к чату. Приглашения не выдают системные права; администратора семьи назначает владелец или администратор приложения, не обычный участник/администратор семьи.
- Смена своего пароля доступна из профиля; минимальную длину задаёт администратор приложения. Сохраняй отдельные формы настроек приложения и текущей семьи, пояснения прав и поиск в длинных списках пользователей.
- На desktop: пространство сверху слева, пользователь снизу слева. На телефоне: список и выбранный чат — отдельные экраны с возвратом. Элементы компактны, но удобны для касания.
- Поддерживай RU/EN, светлую/тёмную/контрастную и системную палитры через общие токены; пользовательский текст не переводи.
- Не перерисовывай целиком чат при реакции, статусе или повторном событии. Сохраняй DOM, прокрутку, фокус, черновики и фильтры. Повторы запросов/событий не должны дублировать действия.
- Ответ выделяется отдельной цитатой с первой строкой исходного текста. Отправка — также Ctrl+Enter/Cmd+Enter. Сохраняй вложения через долгое нажатие отправки; не добавляй видимые кнопки вложений/эмодзи без нового согласования.
- Доставка и прочтение — разные подтверждения; загрузка истории не означает прочтение. Сохраняй проверки видимости и активности клиента.
- «Дела и покупки»: семейная изоляция, необязательная дата, отдельное время завершения, комментарии/история, обратимый архив, контроль версии. Автор/администратор редактируют; участники создают, комментируют и отмечают выполнение. Подробности — docs/family-needs.md.
- Личные дела/покупки доступны без семьи только владельцу, не администраторам; хранятся в той же таблице с взаимоисключающими family_id/owner_user_id. Семейные права относятся только к семейным записям; личный список не зависит от выбранной семьи. Перенос личное ↔ семейное разрешён автору с подтверждением и контролем версии: только в семью с действующим членством; в личное снимается исполнитель, история сохраняется. Администратор не может забирать чужие записи.
- Не расширяй объём самовольно: треды, отдельный раздел «Непрочитанные», повторения/напоминания дел и Huawei Push Kit пока отложены. Существующие счётчики непрочитанных сохраняй.
- Исключение для согласованной личной автоматизации: ежедневный отчёт в диалог с собой по текущим личным и назначенным пользователю семейным делам/покупкам. По умолчанию выключен, время с IANA-зоной; планировщик серверный, сообщение и дневной маркер атомарны, дубли/досылка пачки пропущенных дней недопустимы. См. docs/automations.md.

## Android и эксплуатация

- APK 0.3.0+ — удалённая HTTPS-оболочка. Для правок web/ обновляется сервер; APK нужен при изменениях нативного кода, зависимостей, конфигурации или встроенных страниц.
- Обновления APK: отдельный downloads/android, фиксированный HTTPS-origin, проверка размера/SHA-256/пакета/версии/подписи и системное подтверждение. Debug APK разрешены пользователем, обозначай их тестовыми, не блокируй по типу сборки. Не меняй ключ подписи; APK и latest.json публикуй только по запросу на сервер, описание последним. См. docs/mobile/updates.md.
- Сохраняй allowlist origin/навигации, capabilities старых APK, проверку TLS и ограничения нативного моста. Не разрешай произвольный WebView-origin или mixed content.
- Вложения через «Поделиться» отправляются только после выбора получателя и подтверждения; очередь привязана к аккаунту, повторы идемпотентны. FCM требует сервисов Google; не обещай его работу на Huawei без GMS.
- Перед деплоем проверь целевой хост и домен по актуальным локальным настройкам, не по памяти. SSH — по ключу; парольный вход не включай.
- На текущем VPS запускай Compose через `python3 deploy/compose.py`: обёртка передаёт только Firebase serviceAccount через окружение и сохраняет backup override. Не монтируй settings.local.json в app — там host-only токен и ключ бэкапов. Не выводи Compose config или окружение контейнера. Бэкапы: 02:30 Europe/Moscow; ключ не менять после init, восстановление — только изолированно до отдельного согласования.
- На малом VPS не компилируй Go. Сборка Linux amd64 локально/CI; на сервере только runtime-образ. До миграций — резервная копия и план отката; сохраняй БД и вложения.
- Не меняй MTU 1450, прокси или сеть без диагностики и необходимости. После деплоя проверь контейнеры, health, HTTPS, версию ресурсов, ошибки и память. Не объявляй успех только по завершению команды.

## Проверки и справка

- Go: gofmt, go test ./..., при необходимости go build ./...; git diff --check.
- Web: node --check изменённых модулей; node --test web/*.test.mjs с jsdom через TEST_JSDOM_PATH. Пропущенный DOM-тест не считается успешной проверкой.
- PostgreSQL: TEST_DATABASE_URL только отдельной тестовой БД; никогда рабочая база. Проверяй миграции, роли, семейную изоляцию и повторы.
- Android при нативных изменениях: sync, assembleDebug, testDebugUnitTest, lintDebug. Отдельно отмечай непроверенные сценарии на реальном Safari/Android.
- Обновляй README и тематическую справку вместе с поведением. Различай код, опубликованный релиз и состояние развёртывания; исторические release notes не переписывай под текущую версию.
- Справка: README.md, docs/operations.md, docs/family-needs.md, docs/mobile/android.md, apps/mobile/README.md, docs/ROADMAP.md.
