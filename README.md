## Статусы сообщений

### Сеть рабочего сервера

В `docker-compose.production.yml` MTU сети задан равным 1450 — MTU внешнего интерфейса текущего VPS. При переносе на другой сервер сверяйте это значение с его сетью: превышение доступного MTU может приводить к таймаутам TLS при отправке Web Push. Изменение MTU существующей Docker-сети требует её пересоздания с контейнерами; не удаляйте тома БД и вложений.

Для текущей версии библиотеки Web Push `VAPID_SUBJECT` задаётся адресом электронной почты, с префиксом `mailto:` или без него. Приложение нормализует значение перед формированием JWT, исключая двойной префикс. Отказы push-провайдера журналируются по HTTP-статусу без записи токенов и адресов подписок; сетевой запрос ограничен 15 секундами.

### Значение отметок

- «Отправлено»: сервер сохранил сообщение.
- «Доставлено»: подключённый веб-клиент получателя подтвердил получение уведомления о сообщении; открывать сам диалог не обязательно. Одного Web Push-уведомления без работающего клиента недостаточно.
- «Прочитано»: сообщение остаётся в видимой области открытого чата в активной вкладке между двумя проверками с интервалом 500 мс. Фоновая вкладка, скрытый мобильный экран чата и открытое модальное окно не подтверждают прочтение. Это техническая отметка показа, а не гарантия, что человек прочёл текст.
- В группе доставка и прочтение означают подтверждение всех текущих участников, кроме автора. Для сообщений самому себе остаётся «Отправлено».
- Загрузка истории не меняет статусы. WebSocket обновляет только галочки; переподключение и контрольная синхронизация каждые 30 секунд восстанавливают пропущенные подтверждения.
- Миграция 018 добавляет подтверждения отдельных сообщений и сохраняет ранее накопленные отметки. Исторические ошибочные отметки прежнего клиента автоматически не отменяются.

## Push-уведомления

Для Web Push нужно однократно сгенерировать VAPID-ключи и безопасно передать их в окружение
серверного процесса. Локальные копии секретов — только в settings.local.json.
После входа пользователь нажимает «Включить уведомления» в меню пользователя.

Нативный Android push использует FCM и требует Firebase-конфигурации и сервисов Google.
Huawei Push Kit пока отложен; на EMUI без GMS доставка через FCM не обеспечивается.

На iPhone уведомления работают для приложения, добавленного на домашний экран, на iOS/iPadOS 16.4 и новее.

## Конфигурация

| Переменная | Назначение |
|---|---|
| `APP_ADDR` | Адрес HTTP-сервера, по умолчанию `:8080` |
| `SESSION_SECRET` | Секрет подписи сессий, минимум 32 символа |
| `BOOTSTRAP_ADMIN_EMAIL` | Адрес первого администратора |
| `BOOTSTRAP_ADMIN_PASSWORD` | Пароль первого администратора, минимум 12 символов |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Docker Compose |
| `DATABASE_URL` | Строка подключения вне Compose |
| `MAX_UPLOAD_BYTES` | Максимальный размер вложения |
| `UPLOAD_DIR` | Каталог локального файлового хранилища |
| `DELETED_RETENTION_DAYS` | Срок хранения мягко удалённых сообщений в днях, по умолчанию `30` |
| `VAPID_PUBLIC_KEY` | Открытый ключ Web Push |
| `VAPID_PRIVATE_KEY` | Закрытый ключ Web Push |
| `VAPID_SUBJECT` | Контакт VAPID, например `mailto:admin@example.com` |
| `APP_PUBLIC_URL` | Внешний адрес приложения для ссылок в письмах, например `https://chat.example.com` |
| `APP_DOMAIN` | Домен HTTPS-сайта для Caddy, без протокола |
| `ACME_EMAIL` | Контактный e-mail для выпуска TLS-сертификата |
| `MAIL_HOST`, `MAIL_PORT` | SMTP-сервер и порт; если `MAIL_HOST` пуст, письмо не отправляется |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | Учётные данные SMTP |
| `MAIL_FROM` | Адрес отправителя SMTP-писем |

Никогда не добавляйте в Git `.env`, VAPID private key, SSH-ключи, файлы из `uploads/` или пароли.

## Семьи и роли

### Управление учётными записями

В списке пользователей есть поиск по имени, фамилии и email, фильтры роли/статуса
и страницы по 25 записей. Операции находятся в меню «Действия» строки.
В «Личных» поиск работает по имени и фамилии (email другим участникам не раскрывается).
Поиск учитывает все введённые слова, не зависит от регистра и различия е/ё.
Фильтрация и разбиение на страницы выполняются в клиенте; API пока возвращает полный
доступный список. Для очень крупных установок потребуется серверная пагинация.

Фамилия необязательна при регистрации. Пользователь меняет своё имя и фамилию через
«Мой профиль → Имя и фамилия». В списках и личных диалогах отображается составное имя.
В общем семейном чате подпись автора — имя и отображаемый статус в этой семье
(формат «Статус (Имя)», например, «Мама (Анна)»), без фамилии. Пустой статус и «Неопределено» не выводятся — остаётся имя. Новый формат развёрнут 2026-09-17 миграцией 025.
Статус определяется семьёй сообщения, а не выбранным сейчас пространством.
История и поиск используют одну подпись; сохранённый текст старых цитат не переписывается.
Миграция `022_user_names.sql` сохраняет прежнее отображаемое имя как имя и оставляет
фамилию пустой: автоматическое разделение старых записей не выполняется.

В «Администрировании приложения» доступны деактивация, повторная активация и удаление
аккаунта. Только администратор приложения (`manage_application`) может выполнять эти
действия; роль владельца/администратора семьи сама по себе такого права не даёт.
Необходимо подтвердить точный email выбранной записи. Свой и системный аккаунт
изменить этими действиями нельзя; последний активный администратор защищён также
от снятия административных прав.

Деактивация сохраняет историю, запрещает вход, отзывает старые сессии и push-подписки.
Открытые WebSocket-соединения проверяются перед отправкой события и каждые 5 секунд.
После активации нужен новый вход и повторное включение уведомлений. Уже начатые
запросы/отправленные провайдеру уведомления нельзя гарантированно отменить.
Удаление необратимо и разрешается только при отсутствии истории и связанных данных
(сообщений, созданных чатов/семей/покупок, реакций, подтверждений сообщений, отправок
вложений, истории личных диалогов, аватара). Иначе используйте деактивацию.
Требуется миграция `021_user_lifecycle.sql` перед использованием нового интерфейса.

Каждая семья имеет собственный общий чат. Личные диалоги и произвольные группы
глобальны и не принадлежат семье. Семейные роли не дают прав управления независимой
группой. Межсемейные чаты используют отдельное подтверждение и состав представителей.

- `owner` — владелец семьи: меняет роли участников, категории и отображаемые статусы; последнего владельца нельзя понизить.
- `admin` — администратор семьи: создаёт приглашения, управляет категориями, отображаемыми статусами и своей стороной межсемейных чатов, но не меняет семейные роли доступа.
- `member` — участник семьи без административных полномочий.

Категории — независимая от роли классификация для семейных разделов и будущих адресных функций. Владелец или администратор семьи может назначить одну или несколько категорий: «ребёнок», «родитель», «бабушка / дедушка», «опекун», «родственник». Существующим пользователям категории не назначаются автоматически.

Право `manage_application` — отдельная роль администратора приложения. Оно открывает администрирование учётных записей, прав приложения и политики минимальной длины пароля; семейные администраторы его автоматически не получают.

## Разработка и тесты

На VPS с 1 ГБ памяти не запускайте сборку Go вместе с рабочими сервисами.
Скомпилируйте бинарный файл `familychat` с `CGO_ENABLED=0 GOOS=linux GOARCH=amd64` локально или в CI.
Передайте его вместе с каталогом `web` и `deploy/Dockerfile.runtime` в отдельный каталог сборки на сервере.
Runtime-образ собирается из этого каталога командой `docker build -f Dockerfile.runtime -t chatfamily-app:latest .` без компилятора Go.
После резервного копирования примените обновление через `python3 deploy/compose.py up -d --no-build --no-deps app` и проверьте `/healthz`. После миграции 030 старый образ с семейной моделью групп несовместим: простой откат образа недопустим. См. [порядок развёртывания](docs/operations.md).

```sh
go test ./...
go build ./...
node --check web/app.js
node --test web/*.test.mjs
```

Проверки сохранения DOM и обработки повторных событий: `node --test web/dom-sync.test.mjs`.
Для них установите `jsdom` в отдельный тестовый каталог и укажите путь к модулю в `TEST_JSDOM_PATH`; без него эти проверки пропускаются.

PostgreSQL-интеграционные тесты требуют TEST_DATABASE_URL в окружении и отдельной
тестовой базы. Запускайте `go test ./internal/store`: проверяются миграции, роли,
семейные подписи, дела/покупки, жизненный цикл аккаунта и мобильная дедупликация.
Никогда не указывайте рабочую БД и не помещайте строку подключения в историю команд.

## Текущие ограничения

- межсемейный чат связывает две семьи; автоматического повторного открытия закрытого чата нет;
- новые участники получают всю доступную историю после подтверждения; уже скачанные копии отозвать невозможно;
- получение объектов из буфера зависит от ОС/браузера; физическая приёмка Safari/Android остаётся отдельной проверкой;
- вложения хранятся в постоянном томе VPS и входят в зашифрованные бэкапы; автоматического переключения на другой сервер нет, S3 пока не требуется;
- автоматические бэкапы требуют отдельной аварийной копии ключа и внешнего мониторинга пропущенных запусков;
- цитирование ответа пока хранится в тексте сообщения, без отдельного поля связи в базе;
- сообщения об ошибках, возвращаемые сервером, пока могут отображаться на русском языке;
- дела и покупки пока не поддерживают количество, цену, повторения, подзадачи и автоматические напоминания; списки и история загружаются целиком;
- лог аудита административных действий пока не ведётся.

## Администрирование семей

Создатель семьи становится её владельцем. В меню пространства доступно «Управление семьёй»: владелец или администратор меняет категории и отображаемые статусы участников; роли доступа меняет владелец, а также администратор приложения в отдельном разделе. Общий чат отображается под названием семьи. «Пригласить» создаёт одноразовый код; администратор семьи приглашает обычных участников, назначение административной роли доступно владельцу. Код отправляется по SMTP при заполненных `MAIL_*`; также показывается для безопасной ручной передачи. Независимые группы и межсемейные чаты имеют отдельные правила состава.

Зарегистрировавшийся пользователь не привязан к семье и может создать собственную — это создаёт новую ветвь. Администратор приложения управляет глобальными учётными записями, правами и всеми семьями через отдельные экраны. Эти права не предоставляют автоматическое членство или доступ к переписке, вложениям и делам.

Для SMTP задайте `APP_PUBLIC_URL`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` и `MAIL_FROM`. Не сохраняйте эти значения в Git.
