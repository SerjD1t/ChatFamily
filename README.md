# ChatFamily

Семейный веб-чат на Go и PostgreSQL. Актуальный релиз — **v0.8.0**.

## Возможности

- несколько изолированных семей в одной установке: у каждой свой общий чат, группы, приглашения и администраторы;
- глобальные личные сообщения: любой зарегистрированный пользователь может написать любому другому участнику установки;
- две независимые административные роли: администратор приложения управляет установкой, администратор семьи — только своей семьёй;
- фиксированные категории участников семьи: ребёнок, родитель, бабушка/дедушка, опекун и родственник;
- учётные записи и одноразовые приглашения;
- системные разделы «Семья», «Личные» и «Все группы»;
- избранные группы с персональным списком для каждого пользователя;
- личные диалоги, группы и управление участниками групп;
- счётчики непрочитанных сообщений для групп и личных бесед;
- сообщения, цитирование ответа, реакции, редактирование и мягкое удаление;
- вложения с доступом только участникам беседы;
- обновления в реальном времени через WebSocket;
- Web Push-уведомления для сообщений и реакций;
- PWA-интерфейс для устройств iOS и Android;
- автоматические PostgreSQL-миграции при запуске;
- ограничение частоты критичных запросов и таймауты HTTP/SQL.
- смена пароля из карточки пользователя и настраиваемая минимальная длина пароля.

## Быстрый запуск

1. Скопируйте `.env.example` в `.env`.
2. Задайте уникальные `SESSION_SECRET`, `BOOTSTRAP_ADMIN_PASSWORD` и `POSTGRES_PASSWORD`.
3. Запустите:

   ```sh
   docker compose up --build
   ```

4. Откройте `http://localhost:8080` и войдите с `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`.

PostgreSQL запускается в том же Compose-проекте. Приложение ожидает готовности БД и применяет миграции автоматически.

## Push-уведомления

Для Web Push нужно однократно сгенерировать VAPID-ключи и задать их только в `.env` на сервере. После входа пользователь нажимает «Включить уведомления» в меню пользователя.

На iPhone уведомления работают для приложения, добавленного на домашний экран, на iOS/iPadOS 16.4 и новее.

## Конфигурация

| Переменная | Назначение |
|---|---|
| `APP_ADDR` | Адрес HTTP-сервера, по умолчанию `:8080` |
| `SESSION_SECRET` | Секрет подписи сессий, минимум 32 символа |
| `BOOTSTRAP_ADMIN_EMAIL` | Адрес первого администратора |
| `BOOTSTRAP_ADMIN_PASSWORD` | Пароль первого администратора, минимум 12 символов |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Docker Compose |
| `DATABASE_URL` | Строка подключения вне Compose |
| `MAX_UPLOAD_BYTES` | Максимальный размер вложения |
| `UPLOAD_DIR` | Каталог локального файлового хранилища |
| `DELETED_RETENTION_DAYS` | Срок хранения мягко удалённых сообщений в днях, по умолчанию `30` |
| `VAPID_PUBLIC_KEY` | Открытый ключ Web Push |
| `VAPID_PRIVATE_KEY` | Закрытый ключ Web Push |
| `VAPID_SUBJECT` | Контакт VAPID, например `mailto:admin@example.com` |
| `APP_PUBLIC_URL` | Внешний адрес приложения для ссылок в письмах, например `https://chat.example.com` |
| `MAIL_HOST`, `MAIL_PORT` | SMTP-сервер и порт; если `MAIL_HOST` пуст, письмо не отправляется |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | Учётные данные SMTP |
| `MAIL_FROM` | Адрес отправителя SMTP-писем |

Никогда не добавляйте в Git `.env`, VAPID private key, SSH-ключи, файлы из `uploads/` или пароли.

## Подключение нового пользователя

1. Владелец или администратор семьи открывает меню выбранной семьи и создаёт приглашение для неё, указывая e-mail, роль и отображаемый статус.
2. Новый пользователь на странице входа выбирает «Есть одноразовый код?», вводит код, имя и пароль.
3. После принятия приглашения пользователь входит в чат и добавляется только в семью, указанную в приглашении.

Уже зарегистрированный пользователь может войти и принять код приглашения без создания новой учётной записи.

## Семьи и роли

Каждая семья имеет собственный системный чат и группы. Личные диалоги остаются глобальными и не принадлежат семье.

- `owner` — владелец семьи: меняет роли участников, их категории и отображаемые статусы; последнего владельца нельзя понизить.
- `admin` — администратор семьи: создаёт приглашения, управляет группами и изменяет отображаемые статусы, но не меняет роли и категории.
- `member` — участник семьи без административных полномочий.

Категории — независимая от роли классификация для будущих семейных функций. Владелец может назначить одну или несколько: «ребёнок», «родитель», «бабушка / дедушка», «опекун», «родственник». Существующим пользователям категории не назначаются автоматически.

Право `manage_application` — отдельная роль администратора приложения. Оно открывает администрирование учётных записей, прав приложения и политики минимальной длины пароля; семейные администраторы его автоматически не получают.


## Основные API-маршруты

- `POST /api/v1/auth/login`, `POST /api/v1/auth/register`, `POST /api/v1/auth/logout`, `GET /api/v1/auth/me`, `POST /api/v1/auth/change-password`;
- `GET /api/v1/password-policy`, `GET, PUT /api/v1/application/settings`;
- `GET, POST /api/v1/families`, `PATCH /api/v1/families/{familyID}/members/{userID}`;
- `POST /api/v1/invitations`, `POST /api/v1/invitations/accept`, `POST /api/v1/invitations/join-by-code`;
- `GET /api/v1/conversations`, `POST /api/v1/conversations`;
- `PATCH, DELETE /api/v1/conversations/{id}`, `GET /api/v1/conversations/{id}/search`;
- `GET /api/v1/favorites`, `PUT /api/v1/conversations/{id}/favorite`;
- `POST /api/v1/users/{userID}/direct-conversation`;
- `GET, POST /api/v1/conversations/{id}/messages`;
- `POST /api/v1/messages/{id}/reactions`;
- `POST /api/v1/attachments`, `GET /api/v1/attachments/{id}`;
- `GET /api/v1/events` — WebSocket;
- `GET /api/v1/push/public-key`, `POST/DELETE /api/v1/push/subscriptions`.

## Разработка и тесты

```sh
go test ./...
go build ./...
node --input-type=module --check < web/app.js
```

PostgreSQL-интеграционные тесты требуют отдельной базы:

```sh
TEST_DATABASE_URL='postgres://…' go test ./internal/store -run TestPostgresRepositoryRoundTrip
```

Тест создаёт записи только с префиксом `test_` и удаляет их после выполнения.

## Текущие ограничения

- вложения хранятся на локальном диске контейнера; для отказоустойчивости требуется внешнее S3-совместимое хранилище;
- нет автоматического резервного копирования PostgreSQL и файлов;
- цитирование ответа пока хранится в тексте сообщения, без отдельного поля связи в базе;
- лог аудита административных действий пока не ведётся.

## Администрирование семей

Создатель семьи становится её владельцем. В системном чате «Семья» владелец или администратор семьи открывает «Управление семьёй», где меняет права и семейный статус существующих участников. Кнопка «Пригласить» создаёт одноразовый код для выбранной семьи: назначаются роль `Участник` или `Администратор семьи` и статус (например, «сын»). Код отправляется по SMTP при заполненных `MAIL_*`; также он показывается администратору для безопасной ручной передачи.

Зарегистрировавшийся пользователь не привязан к семье и может создать собственную — это создаёт новую ветвь. Администратор приложения управляет только глобальными учётными записями и правами приложения; он не вступает в семью и не участвует в её создании автоматически.

Для SMTP задайте `APP_PUBLIC_URL`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` и `MAIL_FROM`. Не сохраняйте эти значения в Git.
