# Разработка и безопасное развёртывание

Правила работы: [AGENTS.md](../AGENTS.md). Последние выполненные действия и проверки — в [work-log.md](../work-log.md); запись в журнале не заменяет проверку текущего сервера.

## Конфигурация

Единственный разрешённый локальный файл с секретами — корневой settings.local.json, исключённый из Git и Docker-контекста. Значения не выводить и не копировать в другие файлы проекта. Имена переменных окружения перечислены в README; .env.example — только справочный шаблон.

Основная Go-конфигурация читается из окружения (internal/config/config.go). Загрузки всех параметров из settings.local.json пока нет; отдельный загрузчик используется для Firebase. Для локального запуска заранее настройте изолированную PostgreSQL и безопасно передайте переменные процессу, без значений в командах/истории терминала, затем выполните:

```sh
go run .
```

Важно: текущий docker-compose.yml содержит обязательный env_file: .env. Поэтому запуск Compose на чистом рабочем каталоге не является готовым способом запуска при новом правиле локальных секретов. Не создавайте .env с копией settings.local.json: адаптацию конфигурации Compose нужно выполнить отдельной задачей. Действующее серверное окружение не удалять и не переписывать автоматически.

Проверка исключения без чтения секретов:

```sh
git check-ignore settings.local.json
```

## Проверки

Автономное резервное копирование с Яндекс Диском: [настройка, ограничения и восстановление](backups.md).
Реализация локальная, не включена на рабочем сервере. BACKUP_CONTROL_DIR подключает
только несекретный каталог управления к web-приложению; секреты остаются у host worker.

```sh
go test ./...
go build ./...
node --check web/app.js
node --test web/*.test.mjs
git diff --check
```

DOM-тестам нужен jsdom: установить в отдельный тестовый каталог и передать путь к модулю через TEST_JSDOM_PATH. Проверять число пропусков.
Интеграционным тестам нужен TEST_DATABASE_URL, безопасно переданный через окружение, только на отдельную тестовую БД. Они применяют миграции и создают/удаляют фикстуры; не запускать на рабочей базе.

## Чек-лист развёртывания

1. Получить запрос на обновление сервера. Подтвердить целевой хост по локальным настройкам, домен и текущую версию. Не печатать параметры доступа.
2. Запустить тесты. Собрать Go локально/CI для Linux amd64 с CGO_ENABLED=0; не компилировать на VPS с рабочими сервисами.
3. Создать резервную копию PostgreSQL, проверить её читаемость; учесть сохранность тома вложений. Сохранить предыдущий образ и конфигурацию запуска.
4. Перенести бинарник, web/ и deploy/Dockerfile.runtime в отдельный каталог. Собрать runtime-образ с уникальным тегом и явно выбрать его в конфигурации запуска.
5. Обновить только app через Compose с --no-build --no-deps. Не удалять тома и не пересоздавать сеть без отдельной необходимости. Миграции встроены в бинарник и применяются при старте.
6. Проверить health, HTTPS, нужные статические ресурсы, версию образа, контейнеры, миграции, ошибки и память. Для изменённого функционала выполнить безопасную приёмку.
7. Записать фактический результат и версию в журнал. Откат образа не равнозначен откату схемы: совместимость с новой миграцией проверять отдельно.

SSH — по ключу с проверкой хоста; парольный вход остаётся отключённым. TLS не отключать. В production Compose зафиксирован MTU 1450; на другом хостинге проверять фактический MTU, не считать число универсальным.
Git commit/push, релиз и развёртывание — независимые операции.

Миниатюры вложений после v0.10.0 опубликованы 2026-09-16: runtime chatfamily-app:20260916-previews с FFmpeg, Poppler и prlimit. Конвертеры проверены под лимитами Linux до переключения приложения. Для сборки использован docker build --network host: проверка показала доступ к Alpine-репозиторию из host и таймаут из стандартной bridge-сети. Рабочая сеть/MTU не менялись. При последующих сборках повторно проверить доступ и свободное место; см. docs/attachment-previews.md.

## Версии и ограничения

Код релиза: **v0.11.0**, см. [описание](releases/v0.11.0.md). Публикация в GitHub не выполняет развёртывание.

Последнее подтверждённое развёртывание: **2026-09-17**, runtime `chatfamily-app:20260917-no-family`, схема **025**. Исправлены личные диалоги без семьи; также включены предыдущие доработки оформления, семей и прочтений. Резервные копии `before-20260917-no-family` (.dump, -uploads.tar, -launch.tar) находятся в /opt/chatfamily-backups; образ отката `chatfamily-app:rollback-before-no-family`. Тогда проверены Go/41 web-тест, HTTPS/health, точные ресурсы, образ и отсутствие ошибок/перезапусков. Это запись о выполненной проверке, а не мониторинг текущего состояния.

Автоматические резервные копии из v0.11.0 **не установлены и не включены на VPS**. Для включения нужен отдельный пароль restic, установка host worker/systemd/Compose override и приёмка восстановления. Секреты не включать в образ, Git и release assets. См. [backup runbook](backups.md).
