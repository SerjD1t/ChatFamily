# Обновление Android-клиента

Реализовано в APK 0.5.0 (versionCode 5), серверная поддержка — v0.12.0.
Публикация на VPS фиксируется в [журнале развёртываний](../operations.md).
0.5.0 опубликована 2026-09-18: [скачать APK](https://www.chatfamily.site/downloads/android/chatfamily-5.apk).
Сборка debug, первая установка вручную поверх прежней с совпадающим ключом.
Веб-интерфейс по-прежнему обновляется сервером; APK нужен только для нативных изменений.
Для первого включения механизма установить 0.5.0 вручную и обновить web/ на сервере.
Старые APK без capability `appUpdates` продолжают работать без нового пункта меню.

## Пользовательский сценарий

- После входа и при возврате в видимое приложение проверяется описание обновления.
  Успешные автоматические проверки — не чаще раза в сутки, повтор после ошибки —
  не чаще раза в час. Постоянной фоновой службы нет.
- Меню пользователя → «Версия приложения … · Проверить обновления» запускает
  проверку вручную, без суточного ограничения.
- Предложение показывает версию, размер, изменения и пометку debug для тестовых
  сборок. «Позже» ничего не скачивает. Debug-сборки разрешены по решению пользователя.
- «Обновить» скачивает APK и проверяет его перед открытием системного установщика.
  Для Android 8+ при необходимости предлагается разрешить установку из ChatFamily.
  После возврата из настроек установка требует системного подтверждения.
- Google Play/GMS/FCM не нужны. Фактический сценарий EMUI требует проверки на телефоне.
- Сбой сети, отмена или отказ в разрешении не удаляют чат, настройки и очередь вложений.
  Повтор доступен через ручную проверку. Скачивание после обрыва начинается заново.

## Хранение и безопасность

На VPS отдельный каталог `/opt/chatfamily/downloads/android`, в Compose он подключён
к приложению read-only как `/app/downloads/android`. Не смешивать с uploads/.
Маршруты публичны и предназначены только для публикационных файлов:

- `https://www.chatfamily.site/downloads/android/latest.json`
- `https://www.chatfamily.site/downloads/android/chatfamily-5.apk` (номер versionCode)

Описание содержит packageName, versionCode, versionName, minSdk, path, size, sha256,
debug и notes. Личных данных и ключей здесь быть не должно. Списка каталога нет:
обработчик отдаёт только latest.json и `chatfamily-<число>.apk`; символические ссылки
на файлы не обслуживаются. latest.json выдаётся с Cache-Control: no-store.

Нативный код не принимает URL APK из JavaScript. Разрешены фиксированный HTTPS-хост
и строго соответствующий версии путь; редиректы запрещены. Размер ограничен 128 МиБ,
описание — 32 КиБ; заданы сетевые таймауты. Проверяются размер, SHA-256, имя пакета,
более высокий versionCode, versionName, minSdk и совпадение сертификатов установленного
и нового пакета. Системный установщик дополнительно проверяет APK. Ротация ключей
подписи в первой реализации не поддерживается.

Тестовая подпись не блокируется. Нужно сохранить существующий ключ: новый debug-ключ
на другом компьютере даст несовместимое обновление. Не удалять приложение для обхода
этой проверки: можно потерять локальную очередь и настройки. Ключ подписи не хранить
в публичном каталоге или Git. Перед первым распространением сверить подпись старого
распространённого APK; наличие локального debug-ключа не доказывает её совпадение.

На телефоне используется отдельный cache/app-updates: один APK и временный part-файл,
без внешнего хранилища и без смешивания с вложениями. При новой загрузке предыдущий
APK заменяется, незавершённый part удаляется при следующей проверке; после ошибки
загрузки оба удаляются. Старый APK старше 7 дней или после обновления удаляется при
следующей проверке. Проверка перед установкой повторяется, в том числе после выдачи
разрешения. При выгрузке процесса повтор запустить из меню.

## Подготовка и публикация

1. Увеличить versionCode/versionName в apps/mobile/android/app/build.gradle.
2. Собрать и проверить APK (sync, assembleDebug, testDebugUnitTest, lintDebug).
3. Подготовить локальные файлы:

```text
node apps/mobile/scripts/prepare-update.mjs <signed.apk> <Android-SDK/build-tools/35.0.0> [notes.txt]
```

Скрипт проверяет подпись через apksigner, извлекает параметры через aapt, вычисляет
SHA-256 и создаёт downloads/android/. Debug разрешён с предупреждением. Другой APK
под уже существующим versionCode не перезаписывается; понижение версии latest запрещено.
Описание публикуется атомарно последним. Скрипт не подключается к серверу и не делает push.
Каталог downloads/ и APK исключены из Git и Docker-контекста.

4. По отдельному запросу на деплой перенести сначала APK, проверить хеш, затем
   атомарно заменить latest.json. Каталог должен быть читаем пользователем контейнера.
   Для первого включения также нужны новый серверный бинарник, web/ и bind mount Compose.
   Запускать Compose через python3 deploy/compose.py, не менять backup override.
5. Проверить HTTPS, метаданные, скачивание и обновление поверх предыдущего APK.
   Хранить текущий и 1–2 предыдущих APK; очистка старых серверных сборок пока ручная,
   не удалять файл, на который указывает latest.json. Бэкап данных чата не заменяет
   сохранение исходного APK и ключа подписи.

## Приёмка

Автотесты проверяют policy URL/размера/подписей, подготовку debug/release-метаданных,
ограничения HTTP-маршрута и web-кнопку/повтор/сохранение DOM чата.
Вручную на Android и EMUI: обновление поверх с тем же ключом, отказ с чужим ключом,
битый APK, отсутствие сети/места, отмена, разрешение установки/отказ, возврат из
настроек, сворачивание во время загрузки, повторный запуск и сохранность очереди.
