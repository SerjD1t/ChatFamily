Опубликован 2026-09-23 APK **0.9.1 / код 12**: булавки в карточках покупок и круглый
ряд непрочитанных чатов в виджете. Сервер/web с миграцией 035 обновлены.
[Скачать тестовый APK](https://www.chatfamily.site/downloads/android/chatfamily-12.apk).
[Подробности виджета](family-widget.md).

Обычный вход не открывает старые черновики отправки. APK передаёт одноразовый сигнал
только для нового «Поделиться», а не при восстановлении старого Intent из истории.
После закрытия окно само не появляется; поздний импорт после обычного входа остаётся
в очереди без открытия. Неотправленные вложения доступны из меню пользователя.
На старых APK первый снимок очереди тоже не открывает окно: при холодном запуске
отправку нужно открыть через меню, при уже загруженном интерфейсе новый черновик обнаруживается.

## Навигация по чатам

«Назад» возвращает к списку, сохраняя выбранный чат, историю и черновик.
Повторное нажатие на тот же семейный чат или группу снова открывает окно без
промежуточного перехода в другую группу. То же правило действует для «Дел и покупок».
Фоновое обновление не открывает скрытый экран. Исправление опубликовано на сервере
2026-09-17, runtime `chatfamily-app:20260917-mobile-reopen`; пересборка APK не нужна.

## Сценарий

1. Другое приложение передаёт `ACTION_SEND` / `ACTION_SEND_MULTIPLE`.
2. Android-часть принимает текст и/или файлы. Допустимы только `content://` URI;
   файлы копируются в `noBackupFilesDir/incoming-shares/<UUID>/` вне резервного копирования.
3. После входа пользователь открывает «Входящие вложения», выбирает отправку,
   чат/контакт/диалог с собой, проверяет подпись и подтверждает отправку.
   Опубликовано 2026-09-19 (`20260919-forwarding`): после принятия задания
   в очередь окно адресата закрывается автоматически. Это не подтверждение доставки:
   состояние/ошибки остаются доступны через «Входящие вложения» в меню пользователя.
4. WorkManager отправляет multipart напрямую на HTTPS API с cookie текущей сессии.
   Секреты не передаются в JS и не записываются в файлы очереди.
5. Сервер проверяет аккаунт, право отправки и членство в чате. В одной транзакции
   записываются сообщение, вложения и подтверждение идемпотентности.
6. После HTTP-подтверждения локальные копии вложений удаляются. В версии web,
   опубликованной 2026-09-25, успешная отправка исчезает из очереди, отдельной «Истории» нет.
   Служебные подтверждения сохраняются: повтор использует прежний UUID и неизменные параметры.
   После новой успешной отправки открывается чат получателя, без перехода к конкретному
   сообщению. Старые успешные отправки при обычном входе не вызывают переходов.
   При ошибке доступны «Повторить» и «Отменить»; принятие в очередь ещё не означает успех.

Поддерживаются до 10 файлов, 25 МиБ на файл, 100 МиБ на отправку, до 5 активных записей очереди.
«Входящие вложения» доступны в меню пользователя. Получатель выбирается поиском
и компактным списком; в окне остаются только ожидающие и неудачные отправки.
Серверный MAX_UPLOAD_BYTES может дополнительно ограничивать размер файла.
Длинные тексты (>4000 символов), пустые файлы и небезопасные URI отклоняются.
Если источник передал ссылку вместо файла, отправляется текст ссылки после подтверждения.

## Разделение ответственности

- `web/mobile/`: локализация RU/EN, выбор получателя, подпись, состояние очереди;
  обновляется только список очереди, история чата и её черновик не перерисовываются.
- `apps/mobile/android/.../share/`: приём Intent, приватные копии, атомарный JSON
  состояния, системная очередь и уведомление о фоновой передаче.
- `mobile_share_handlers.go`: потоковое чтение multipart, лимиты и отпечаток содержимого.
- `internal/store/mobile_shares.go` и миграция 019: транзакционная дедупликация.
- `mobile_cors.go`: разрешён только фиксированный origin упакованного клиента.

## Безопасность и повторы

Фоновый запрос содержит `X-Expected-User`. При выходе, истечении сессии или смене
аккаунта отправка не выполняется от другого пользователя; требуется войти в исходный
аккаунт и повторить. Подтверждённая очередь другого аккаунта скрыта в интерфейсе.
Неподтверждённые входящие файлы не привязаны к аккаунту — пользователь выбирает его входом.

Ключ идемпотентности уникален на пользователя. Конкурентные повторы сериализуются
транзакционной блокировкой; изменение содержимого с прежним ключом возвращает 409.
Ключ сохраняется после удаления сообщения, чтобы повтор не восстановил удалённое.
На повтор не создаются дополнительные realtime/push-события.
При неопределённом результате COMMIT сервер сохраняет файлы: безопаснее оставить
возможный бесхозный файл, чем удалить вложение уже записанного сообщения.
Автоматическая очистка таких серверных сирот пока не реализована.

TLS-проверка не отключается; HTTP и произвольная навигация WebView не разрешены.
С версии APK 0.3.0 оболочка загружает интерфейс с HTTPS-origin сайта; API и WebSocket
используют тот же origin. Сессионная HttpOnly-cookie остаётся на API-хосте.
Старым APK сохранена совместимость CORS. LocalStorage старого локального origin не
переносится автоматически: при обновлении могут потребоваться настройки языка/темы
и повторное включение уведомлений. Нативная очередь вложений сохраняется.
Содержимое файлов, cookies, имена пользователей и токены в журналы не выводятся.

## Ограничения первой версии

- FCM/native push добавлен в код; доставка требует настройки Firebase в APK и на сервере
  и отдельной проверки на устройстве. Не реализованы iOS-клиент и release-подпись.
- На EMUI без сервисов Google FCM не обеспечивает доставку. Huawei Push Kit отложен;
  не считать отсутствие уведомлений в такой конфигурации неисправностью веб-интерфейса.
- Повторы после сетевых ошибок/429/5xx ограничены шестью попытками, затем доступны вручную.
  Ошибки авторизации/прав/лимитов требуют ручного исправления.
- Android управляет квотами WorkManager и foreground service. Принудительная остановка
  приложения пользователем останавливает работу до повторного запуска. Мгновенная
  фоновая отправка при любых настройках энергосбережения не гарантируется.
- Передача повторяется целиком, а не с места обрыва; дедупликация исключает повтор сообщения.
- Активную отправку нельзя отозвать через UI. Для неуспешной отправки «Убрать» требует
  предупреждения: потерянный HTTP-ответ не означает, что сообщение не было записано.
- Превью изображений в очереди пока нет; показываются имя и размер. Сжатие не выполняется.
- В APK 0.4.0 загруженные для открытия файлы имеют ограниченный кэш (200 МиБ/7 дней
  по умолчанию), повторное использование после проверки доступа и ручную очистку.
  [Память устройства](device-storage.md). Вложения открываются через FileProvider
  с временным доступом, а не через внешний браузер без сессии.

## Обязательная приёмка на устройстве

- Для оболочки 0.3.0: обновить APK поверх предыдущей версии, проверить сессию и настройки;
  запустить без сети, нажать Retry после восстановления; проверить отказ при ошибке TLS.
  HTTPS-ссылки вне экрана приложения должны открываться отдельным браузером, а
  `javascript:`, `intent:`, `file:` и произвольные origins не должны загружаться внутри.
  Старый неограниченный JavaScriptInterface отключён; требуется современный WebView.
  Проверка capabilities сохраняет поддержку старых share-only оболочек без PushEnvironment.
  CSP запрещает frames/objects, но не заменяет защиту от XSS: серверный код имеет доступ
  к разрешённым плагинам. Добавлять новые нативные методы только с проверкой входных данных.

- Холодный и уже открытый клиент: фото, несколько фото, PDF, кириллическое имя,
  текст/ссылка из галереи, файлового менеджера и стороннего мессенджера.
- Вход после получения файла; выбор себя, существующего/нового личного диалога,
  семейного чата другой семьи; отмена до подтверждения.
- Обычный участник с правом отправки, пользователь без права отправки, исключённый
  участник; администратор не должен обходить членство в чужом чате.
- Переход в другой чат во время отправки, смена аккаунта, повтор после обрыва сети,
  сворачивание/блокировка, повторный запуск процесса, отказ в уведомлениях Android.
- Два одинаковых повтора: ровно одно сообщение; отсутствие полной перерисовки истории.
- Отдельно: обычные вложения по долгому нажатию, открытие полученных файлов,
  аватары, WebSocket, выход/повторный вход, переключение RU/EN и палитр.

TEST_JSDOM_PATH). PostgreSQL-тест конкурентной дедупликации запускается только с
