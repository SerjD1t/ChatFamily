# Чаты между семьями

Первый вариант связывает **две семьи**. Это отдельный тип `interfamily`,
не произвольная группа, определённая по составу. Нужна миграция 031 после 030.
Развёрнуто 2026-09-19: `chatfamily-app:20260919-interfamily`. Новый APK не требуется.

## Подключение

1. Владелец/администратор выбирает свою семью и открывает **Семейные чаты →
   Управление семейными чатами → Создать чат**.
2. Задаёт название, пиктограмму и явно отмечает представителей своей семьи.
   Никто, включая самого администратора, не отмечен автоматически.
3. Передаёт одноразовый код администратору второй семьи. Код действует 7 дней;
   при потере или компрометации до подключения можно выпустить новый.
4. Второй администратор выбирает свою семью, открывает **Подключиться по коду**,
   вводит код и явно выбирает своих представителей. Это подтверждение второй стороны.
5. Инициатор обновляет список управления и подтверждает запрос, видя название
   подключаемой семьи. До этого сообщения и вложения недоступны обеим сторонам.

Нет общего каталога чужих семей. На сервере хранится только SHA-256 кода;
код не записывается в browser storage, журналы или документацию. Не передавать
его в публичные чаты. Повтор создания с тем же ключом не создаёт второй чат;
если ответ с кодом потерялся, выпустить новый в управлении.

## Участники и права

- Каждая сторона управляет только своими представителями; обычный участник
  не может подключать семьи или менять состав. Глобальная административная роль
  без роли в семье этих прав не даёт.
- Выбранный представитель получает **всю историю** после активации; интерфейс
  предупреждает об этом. Новые члены семьи автоматически не добавляются.
- Администратор, не выбранный представителем, управляет настройками своей стороны,
  но не читает переписку и вложения. Представители пишут на обычных правах участника.
- Исключение из семьи немедленно убирает её представительство. Повторное вступление
  не восстанавливает его автоматически. Если пользователь явно представляет обе
  семьи, доступ сохраняется через вторую до удаления обоих назначений.
- Название и пиктограмму может менять администратор любой стороны; состав — только
  своей. Изменения защищены общей версией. При конфликте закрыть карточку, обновить
  список и открыть её снова: чужие правки не перезаписываются.
- Любая сторона может подтвердить **закрытие для обеих семей**, в том числе отказ
  от ожидающего запроса. История остаётся в БД, доступ закрывается. Автоматического
  открытия заново нет. Архивирование любой из семей также закрывает общий чат.

## Навигация и эксплуатация

У представителей чат отображается в **Семейных чатах** выбранной семьи; не
дублируется в независимых группах. Смена семьи не сбрасывает уже открытую переписку.
Администраторы видят ожидающие и активные связи через окно управления, даже если
сами не выбраны участниками. Для актуализации открытого управления есть «Обновить список».

Таблицы: `interfamily_chats` (стороны, состояние, версия, хеш приглашения),
`interfamily_representatives` (явный состав, FK на членство семьи).
`conversation_members` синхронизируется после одобрения и при отзыве представительства.
Операции блокируют строки обеих семей в стабильном порядке, затем связь;
это согласовано с исключением участников через семейное администрирование.

Перед миграциями 030–031 — резервная копия БД, вложений и запуска. Старый сервер
с семейной моделью произвольных групп несовместим с 030; автоматического отката
на старый образ не делать. Предпочтителен исправленный совместимый образ.
Восстановление старой БД допустимо только отдельно, без потери новых сообщений.
Нативный Android-код не меняется: новый APK не требуется.
