# Миниатюры вложений

Следующая локальная доработка (ещё не опубликована): все три действия просмотрщика —
контурные иконки скачать, масштаб и закрыть в стиле действий сообщения.
Подсказки/доступные названия RU/EN сохранены; иконка масштаба меняется при переключении.

Опубликовано 2026-09-19 (`20260919-forwarding`): «Скачать» оформлено кнопкой;
масштаб 1:1 переключается иконкой с подсказкой и доступным названием; выход —
кнопка «Закрыть». Нативное открытие/скачивание Android сохранено.

Доработка после v0.10.0, впервые развёрнута 2026-09-16 в runtime chatfamily-app:20260916-previews; актуальный runtime — chatfamily-app:20260916-storage. Исходники включены в main без нового релиза.

В сообщении отображается компактная карточка с названием и размером:

- JPEG, PNG, GIF, WebP, BMP — статичная миниатюра;
- MP4, QuickTime, WebM, Matroska, AVI, MPEG, Ogg video — первый кадр и значок видео;
- PDF — первая страница;
- остальные форматы (включая HEIC, SVG и офисные документы) — иконка без конвертации.

Просмотрщик опубликован 2026-09-18 (`20260918-media-settings`): изображение/видео открывается
поверх чата. Изображение — вписать/масштаб 1:1 с прокруткой, видео — стандартные
управление, перемотка и полноэкранный режим, если он поддерживается браузером.
Автозапуска нет. Закрытие останавливает видео и освобождает источник, сохраняет
историю и черновик. «Скачать» — отдельное действие; PDF/остальные файлы пока скачиваются.
На Android просмотр перехватывается до нативного открытия файла. Нативный код не меняется.
Неподдерживаемый кодек/повреждённый файл показывает ошибку с возможностью скачивания;
транскодирование не добавлено. Физические Safari/Android требуют проверки.

Оригинал через `?inline=1` выдаётся только для разрешённых изображений/видео после
обычной проверки доступа AttachmentObject. `http.ServeContent` поддерживает Range/HEAD,
не загружая весь файл в память сервера. Каждый запрос заново авторизуется; private/no-store,
nosniff. SVG/HTML/PDF запрещены для inline. Миграция/новый APK не нужны.

## Устройство

GET `/api/v1/attachments/{id}/preview` проверяет сессию и доступ через тот же AttachmentObject, что и скачивание. Кэш не выдаётся напрямую из файлового каталога; HTTP private/no-store. Ответ — только проверенный JPEG до 480×480, не активный пользовательский документ.

FFmpeg получает кадр изображения/видео, pdftoppm — страницу PDF. Запуск без shell, имена исходных пользовательских файлов не используются в аргументах, сетевые протоколы и плейлисты FFmpeg запрещены. Linux prlimit ограничивает адресное пространство 384 MiB, CPU 8 секунд, выходной файл 2 MiB; общий таймаут запроса 15 секунд, один декодер одновременно. Это ограничения ресурсов, не полноценная песочница: обновления конвертеров важны.

Кэш `uploads/.previews-v1` содержит миниатюры и пятиминутные маркеры неудачных преобразований. Генерация при первом запросе, старым вложениям миграция не нужна. Кэш производный и может быть удалён администратором при обслуживании; автоматическое удаление осиротевших миниатюр пока не реализовано. Удаление кэша не удаляет оригиналы. Не публиковать этот каталог отдельно. Для ручного обслуживания и переключения миниатюр доступен раздел [Хранилище](storage.md), развёрнутый 2026-09-16.

Изображения загружаются лениво с заранее заданными размерами карточек. Синхронизация сообщений сохраняет узлы миниатюр и состояние ошибки; нет дополнительной загрузки оригинала на клиент.

## Развёртывание и проверка

Обновить бинарник, web/ и runtime-образ вместе. В Dockerfile добавлены ffmpeg, poppler-utils и util-linux (prlimit); установка увеличит размер образа. Перед сборкой проверить свободный диск. Новый APK и миграции не нужны. При локальном запуске нужны ffmpeg и pdftoppm в PATH; Linux также требует prlimit.

Тесты: `go test ./...`; `TEST_PREVIEW_TOOLS=1 go test -run TestPreview -v .` с конвертерами в PATH; `node --test web/*.test.mjs` с jsdom. Проверка конвертеров использует только синтетические файлы.

Ручная приёмка: Safari и Android, большие/повёрнутые фото, повреждённый и защищённый PDF, разные видеокодеки, несколько вложений, сохранение прокрутки при реакциях; запрет доступа чужому пользователю и после выхода из беседы, включая уже созданный кэш. Конвертеры проверены на синтетических файлах в Windows и в отдельном Linux-контейнере под prlimit перед переключением рабочего приложения; неавторизованный запрос preview возвращает 401.
