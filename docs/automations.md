# Личная автоматизация

Добавлено в v0.12.0. Настройки: меню пользователя →
«Мой профиль» → «Автоматизация». Доступны только настройки собственного аккаунта,
в том числе без семьи; администратор не получает доступ к чужим настройкам.

## Ежедневный отчёт

- По умолчанию выключен. Включение — «Отправлять ежедневный отчёт».
- Время задаётся с точностью до минуты, вместе с часовым поясом IANA.
  Начальные значения — 09:00, Europe/Moscow; часовой пояс показан явно и редактируется.
  Настройки сохраняются на сервере и не меняются от смены устройства/семьи.
- По согласованию пользователя: все текущие личные дела и покупки плюс семейные,
  где пользователь назначен исполнителем и по-прежнему состоит в семье.
  Завершённые/архивные и чужие личные записи исключены. Семьи учитываются все,
  а не только выбранная в интерфейсе. Право администрирования не расширяет выборку.
- Сообщение появляется в личном диалоге с собой («Вы»); при необходимости сервер
  создаёт этот диалог. Заголовок явно обозначает ежедневный отчёт. Для чтения
  отдельного аккаунта-бота не нужно. Это системная запись в собственный диалог,
  не отправка от пользователя другим людям; send_messages не требуется.
- Отчёт показывает тип, название, срок, пометки «Просрочено»/«Сегодня», семью или
  личную область. Описания и комментарии не копируются. Если список велик,
  сообщение ограничено 4000 символами и показывает число оставшихся записей.
- Если записей нет, приходит короткий отчёт об отсутствии текущих дел/покупок.
- Формат заголовков соответствует сохранённому языку RU/EN; текст записей не переводится.
- Отдельный push для отчёта пока не добавлен: сообщение хранится на сервере и
  обновляется через WebSocket для владельца; приложение может быть закрыто при отправке.

## Расписание и повторы

Планировщик внутри Go-сервера проверяет очередь при запуске и затем раз в минуту,
обрабатывая до 100 пользователей за проход. При обычной нагрузке сообщение
появляется в течение минуты после заданного времени; это не таймер на телефоне.

Первое включение/смена времени назначает ближайшее будущее время, без немедленной
отправки за прошлое. Сохранение неизменённых настроек не откладывает уже ожидающий
отчёт. При смене часового пояса сохраняется правило не более одного отчёта на
локальную календарную дату. При переходе на летнее время пропущенное время
переносится на первую существующую минуту после него, повторное время — первая
из двух реализаций.

После простоя прошлые дни не досылаются пачкой: отправляется только отчёт текущего
дня, если его время уже наступило; иначе ожидается сегодняшнее время. Деактивированные
аккаунты не обслуживаются. Выключение не удаляет ранее отправленные сообщения;
если транзакция отправки уже началась, она может завершиться до сохранения выключения.

Миграция `027_user_automations.sql`: настройки user_automations и дневные маркеры
daily_report_runs. Блокировка строки настроек и уникальность (user_id, report_date)
защищают от параллельных процессов. Сообщение, маркер и следующее время фиксируются
одной транзакцией. Ошибка откатывает всё; повтор — на следующем проходе.
WebSocket-событие отправляется после commit только владельцу. При обрыве между
commit и событием сообщение остаётся в истории и появится при следующей загрузке.

## API, проверка и публикация

`GET/PUT /api/v1/user/automations`: dailyReportEnabled (boolean), reportTime (HH:MM),
timeZone (IANA). Пользователь определяется по сессии; сервер валидирует время/зону.
Без PostgreSQL возвращается 503, имитации успешного сохранения нет.

Тесты: TestAutomationSchedule (включая DST), TestDailyReportFormatting,
TestDailyReportTransaction (только изолированная TEST_DATABASE_URL),
web/automations.test.mjs (RU/EN, ошибки, повтор, запрет дублированного сохранения).
2026-09-18 все store-тесты пройдены на изолированной PostgreSQL без сети,
включая миграции 026–027 и конкурентную отправку без дублей.

Перед публикацией проверить миграции 026–027 и транзакционный тест в отдельной БД,
сделать резервную копию рабочей БД, обновить сервер и web вместе. Новый APK не нужен.
Вручную: включить время на несколько минут вперёд, закрыть клиент, затем проверить
состав/язык/однократность отчёта в диалоге «Вы», отключение и смену часового пояса.
Для отката поведения остановить новую версию/вернуть предыдущий бинарник; таблицы
и историю не удалять. Секретов/отдельных cron-заданий для этого механизма нет.
