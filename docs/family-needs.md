# Дела и покупки

[Ежедневный личный отчёт](automations.md) настраивается в профиле → «Автоматизация».
Он включает личные и назначенные пользователю семейные записи (v0.12.0).

## Личные и семейные записи (v0.12.0)

Раздел доступен всем вошедшим пользователям, включая пользователей без семьи.
Переключатель «Личные / Семья» выбирает список. Без семьи доступен только личный.
Смена семьи не меняет открытый личный список. Если открыт семейный список,
он остаётся на экране и загружает записи новой семьи; несохранённые семейные
черновики в другую семью не переносятся. При переключении области открывается
отдельный список: записи и черновики между областями не переносятся.

Личные записи видит и изменяет только владелец — права администратора семьи или
приложения не дают доступа. Исполнитель для личных записей не выбирается. Тип,
срок, выполнение, комментарии, история и обратимый архив работают одинаково.
Правила семейных записей, описанные ниже, сохраняются.

Миграция `026_personal_needs.sql` расширяет существующую `shopping_items`:
либо `family_id`, либо `owner_user_id`, ровно одно поле заполнено (CHECK в БД).
Автор хранится отдельно. Существующие семейные записи остаются без изменений.
Перемещение между областями не реализовано.

Личный API: `GET/POST /api/v1/me/needs`, `GET/PATCH /api/v1/me/needs/{itemID}`,
`POST /api/v1/me/needs/{itemID}/comments`; архив — `?archived=true`.
Владелец берётся из авторизованной сессии, не из тела запроса. Чужие ID не дают
доступа через чтение, изменение, комментарии или семейный API. События изменения
личных записей отправляются только соединениям владельца.

До публикации: резервная копия БД, проверка миграции в изолированной PostgreSQL,
затем сервер и web вместе. Откат старой схемы после появления личных записей
нельзя выполнять простым возвратом NOT NULL: сначала сохранить данные и
согласовать восстановление. APK пересобирать не требуется.

В семейной области переключение семьи меняет список; личные дела и диалоги остаются глобальными.

Выбор доступной семьи: название пространства вверху слева → «Текущая семья».
Переключатель показывается при наличии двух и более семей. Семейный чат или
группа при смене семьи переключается на общий чат новой семьи, а личный диалог
сохраняется без перерисовки. Категории участников и список групп остаются в своём
разделе, но показывают новую семью. Эта логика входит в v0.12.0.

Интерфейс «список прежде формы» развёрнут 2026-09-17; новый APK не требуется. Визуальная приёмка на физических устройствах остаётся отдельной проверкой.

## Интерфейс

- При открытии сразу показаны текущие записи. Одинаковая логика на компьютере и телефоне: кнопки поиска/добавления, переключатель «Текущие / Выполненные / Архив», затем список.
- «Добавить» открывает отдельный диалог на компьютере и нижнюю панель на телефоне: название (до 160 символов), тип «Покупка»/«Дело», необязательная дата. Закрытие сохраняет черновик до ухода из раздела; ошибка не стирает ввод, повторное нажатие не дублирует запрос. После успеха окно закрывается, список переходит на текущие без фильтров, чтобы новая запись не скрылась.
- Поиск по названию, описанию и исполнителю и фильтр типа раскрываются по кнопке. При закрытии поиска активные условия остаются видимой строкой со сбросом. Открытие/закрытие карточки не сбрасывает фильтры и положение списка.
- Нажатие на строку открывает краткую карточку: название, тип, срок, исполнитель и описание, сразу под ними — общая лента истории и комментариев. Длинное описание прокручивается отдельно.
- Поля доступны по «Редактировать»; «Отмена» сбрасывает несохранённые правки. Архивирование/восстановление — в «Другие действия». Комментирование не сбрасывает черновик редактирования.
- Выполненную запись можно вернуть в работу снятием галочки. Дата выполнения хранится отдельно от плановой даты.
- Архивирование не удаляет запись или комментарии. Архив доступен для чтения и восстановления.
- Счётчики «Сегодня» и «Просрочено» учитывают только невыполненные неархивные записи. Записи без срока в эти счётчики не входят. Сегодня определяется по локальной календарной дате клиента.

## Права семейной области

Чтение, создание, завершение, возврат в работу и комментарии доступны участникам этой семьи.
Редактирование полей, назначение исполнителя, архивирование и восстановление доступны автору и владельцу/администратору семьи.
Администратор приложения не получает доступа к чужим семейным спискам только на основании глобальной роли.
Исполнителем можно назначить только действующего участника этой семьи с активным аккаунтом.
Ранее назначенный выбывший участник сохраняется в записи, но недоступен для нового назначения.

Права проверяются сервером, а не только видимостью кнопок. Ссылки на запись другой семьи не дают доступа.
Конкурентные изменения проверяются по версии записи; конфликт возвращает HTTP 409. Черновик не затирается: нужно открыть актуальную карточку и повторить правку.
Комментарии неизменяемы в первой версии. На архивные записи новые комментарии не добавляются.

## Хранение и совместимость

Миграция `024_family_needs.sql` расширяет `shopping_items` и добавляет `family_need_activity`.
Существующие покупки, даты и завершение сохраняются. Старые записи получают тип purchase; исторические события задним числом не создаются.
Каждое изменение и его снимки сохраняются в одной транзакции. Повторная установка того же состояния не создаёт лишнее событие.
API: GET/POST `/api/v1/families/{familyID}/needs`, GET/PATCH `.../needs/{itemID}`, POST `.../needs/{itemID}/comments`.
Архив: GET `.../needs?archived=true`. Пустая строка даты/исполнителя очищает соответствующее поле.
Старые маршруты `/shopping` сохранены, используют те же права и историю; DELETE теперь архивирует.
Фоновые события обновляют строки списка, сохраняя форму, поиск и фокус. Открытая карточка показывает предупреждение об изменениях, не затирая введённые данные.

## Проверка перед переносом

Миграции 022–024 и обновлённый сервер/веб-интерфейс нужно переносить вместе. Резервная копия БД обязательна; автоматический откат схемы не предусмотрен.
Новый APK для удалённой оболочки 0.3.0 не требуется.
Автотесты: `go test ./...`, PostgreSQL-тест TestFamilyNeeds в отдельной тестовой БД и `node --test web/*.test.mjs` с установленным jsdom.
Вручную: Safari, Android, узкий экран, обе локали и палитры; две одновременные сессии; создание, назначение, комментарий, завершение, архив и восстановление под автором, участником, администратором и посторонним.
Списки и история пока загружаются целиком: серверная пагинация — следующий шаг при большом объёме данных. Повторения, напоминания, подзадачи и вложения к делам не включены.
