# Оформление интерфейса

Развёрнуто 2026-09-17, runtime `chatfamily-app:20260917-appearance-range`. Новый APK не требуется.

Меню пользователя → Мой профиль → Оформление и язык.

- **Оформление:** Семейное (прежняя зелёная гамма) или Классическое (нейтральные поверхности, синий акцент, небольшие скругления и сдержанные тени).
- **Режим:** как в системе, светлый, тёмный, высококонтрастный. Системный режим реагирует на изменение настройки ОС; высокий контраст работает с обоими скинами.
- **Плотность:** компактная, обычная, просторная. Основные вертикальные отступы примерно 60% / 100% / 140% от обычных; высота ограничивается содержимым и безопасными областями касания. Расположение функций не меняется.
- **Текст:** меньше, обычный, крупнее (основной текст 0.8125 / 1 / 1.3125 rem — 13 / 16 / 21 px при стандартном корневом размере). Корневой размер шрифта, системный масштаб и точки адаптивного переключения не переопределяются.

Предпросмотр применяется сразу, без замены DOM истории. Смена параметров удерживает первое видимое сообщение/дело в области чтения. «Сохранить» фиксирует настройки, «Отмена» или закрытие карточки восстанавливает сохранённый вариант. «Стандартные настройки» сначала только показывает семейное оформление, системный режим, обычные текст и плотность — для фиксации нажмите «Сохранить». Язык сбросом оформления не меняется.

Оформление хранится в localStorage отдельно для аккаунта на каждом устройстве/профиле браузера (ключ familychat.appearance.v1 с идентификатором аккаунта). Между компьютером и телефоном не синхронизируется. Язык остаётся серверной настройкой аккаунта. Пока локальный вариант не сохранён, режим берётся из прежней настройки палитры аккаунта; существующие пользователи автоматически на новый скин не переводятся. Очистка данных сайта сбросит локальное оформление. Ошибка сохранения показывается пользователю.

На узком экране и при сенсорном указателе изменённая плотность сохраняет основные области нажатия не меньше 44 CSS px; компактность достигается прежде всего сокращением отступов. Поля при изменённом размере текста не уменьшаются ниже 16 CSS px, чтобы избежать излишнего масштабирования при фокусе в мобильных браузерах. Полностью одинаковая плотность на мыши и сенсорном экране намеренно не гарантируется.

## Расширение и публикация

Исправление полей в v0.12.0: минимальные 16 CSS px
на сенсорных устройствах действуют для всех режимов текста, включая обычный и
неустановленный. Поля карточки дела ранее наследовали 13,6 px от label, а защитное
правило охватывало только small/large. Автофокус редактирования сохранён; запрет
пользовательского масштабирования и принудительный сброс viewport не добавлялись.
Механизм увеличения полей при фокусе обсуждается в [WebKit](https://bugs.webkit.org/show_bug.cgi?id=157771).
`node web/check-form-layout.mjs` с TEST_PLAYWRIGHT_PATH проверяет в Chromium
60 сочетаний ширины/текста/плотности с сенсорным указателем (включая 820 px).
Реальный iOS-автозум этим тестом не воспроизводится; нужна приёмка iPhone после
публикации. Уже увеличенную страницу может потребоваться перезагрузить или
вручную вернуть к обычному масштабу.

Исправление в v0.12.0: колонка чата ограничена
доступной шириной, редактор сообщения может сжиматься, статусы и длинный текст
переносятся внутри пузыря. На мобильном экране действия шапки вынесены в отдельную
строку под названием; доступные кнопки не скрываются. Это устраняет растягивание
чата вправо, которое маскировалось обрезанием внешнего контейнера.

Проверка геометрии: `node web/check-chat-layout.mjs` с TEST_PLAYWRIGHT_PATH,
указывающим на установленный пакет Playwright. Проверяются 54 сочетания ширин
320/375/390/430/768/1280 px, трёх размеров текста и трёх плотностей в Chromium.
Тест не требует сервера, использует синтетические данные и реальные CSS.
Он не заменяет проверку Safari/iPhone и поведения экранной клавиатуры.

Скины задаются фиксированным списком и семантическими CSS-переменными в web/appearance.css. Пользовательский CSS, внешние ссылки на стили и произвольные размеры не принимаются. Новый скин должен покрывать поверхности, текст, границы, акцент, сообщения, фокус, светлый/тёмный/системный режимы и не ухудшать высокий контраст. Стили подключаются после основных и мобильных.

Для публикации нужен актуальный web/, включая appearance.js и appearance.css. Миграции БД и новый APK не нужны. Unit/DOM-проверки: нормализация, старые настройки, изоляция аккаунтов/устройств, отказ хранилища, предпросмотр/отмена/сброс, сохранение узлов и якоря чтения. Вручную до окончательной приёмки: Android/EMUI, Safari, узкий экран с клавиатурой, длинные подписи RU/EN, системное увеличение, все сочетания скина/режима/плотности/текста. Реальная браузерная геометрия и физические устройства DOM-тестами не проверяются.
